## Built

- **`bytelanes-abi`** (`no_std`, no `unsafe`): the op format, version 1.
  - `ChannelProgram` (1672 bytes: 8-byte header, 16 command slots),
    `ChannelCmd` (104), `Extent` (32), `Completion` (24), `Caps` (16),
    `CryptParams` and `FilterParams` (32 each), `Status`, `PathState`.
  - Every wire struct is `#[repr(C)]` from bytes and `zerocopy`
    little-endian integers: alignment 1, no padding, the same bytes on every
    machine, sizes asserted at compile time. `zerocopy`'s derives compile
    under `#![forbid(unsafe_code)]`, so no `unsafe` is needed.
  - Op semantics, wire layouts and the error-check order are documented on
    the types (`Op`, `ChannelProgram`, `Completion`).
- **`bytelanes`**:
  - `ChannelBackend` (the spec's trait) and `Buffers` (create host buffers,
    allocate device buffers, load keys; not frozen).
  - `verify(completion, result)`: the receiver-side CRC check.
  - `cpu::ops`: CRC-32C through `crc32c`, AES-256-CTR through `aes` 0.9 and
    `ctr` 0.10, Filter as a monomorphised scan.
  - `cpu::CpuBackend`: runs whole programs on the ops.
  - `conformance`: `load_vectors`, `golden_cases`, `random_case(op, seed)`

    the harness agents B and C run for R7.

## Op format decisions for review

The spec gave a sketch; these are the choices that filled it in. All of them
are now the contract.

1. **Buffers by id, not pointer.** `Host` and `Vram` extents carry
   `(buffer id, offset, length)`; the backend resolves ids. Pointers cannot
   cross the network and would need `unsafe`. `Nvme` carries
   `(device, lba, blocks)`.
2. **32 bytes of op parameters** replace the spec's `arg: u64`. Crypt holds
   a key slot and the full 16-byte IV; Filter holds its whole predicate
   inline, so no predicate registry has to be kept in sync across machines.
   Keys never travel in a program: the command names a key slot.
3. **AES-256-CTR counter**: the IV is the first counter block, a 128-bit
   big-endian integer incremented per block and wrapping modulo 2^128
   (NIST SP 800-38A style). `Encrypt` and `Decrypt` are the same transform;
   both are implemented.
4. **Checksum** writes the CRC-32C as 4 little-endian bytes to `dst`.
5. **Filter**: element types `u32`, `i32`, `f32`, `u64`, `i64`, `f64`
   (little-endian); comparisons `Eq`, `Ne`, `Lt`, `Le`, `Gt`, `Ge`,
   `Between` (inclusive); output is ascending `u32` row indices. IEEE 754
   rules for floats: `NaN` matches only `Ne`, and `-0.0 == 0.0`. An output
   form byte leaves room for a bitmap output later.
6. **Idempotency is enforced by validation**: no `dst` may overlap any `src`
   in the same program, except the `src` a chain link feeds. In-place
   decrypt of a host buffer is therefore rejected. This makes spec rule 4
   (resubmit once on another path) safe by construction.
7. **Chains**: `CHAIN` requires the next command's `src` to equal this
   command's `dst`, and every `dst` except the last must be `Vram`. A
   chained input is the previous result's bytes, not the whole extent.
8. **Completion**: one per program. `cmd_index` is the failing command, the
   last command on success, or `0xFFFF` for a program-level failure. `crc`
   is the CRC-32C of the final result. On `DstTooSmall`, `bytes` is the size
   needed.
9. **Error order** per command: unsupported op, unsupported extent kind,
   unknown buffer, out of bounds (`src`, then `dst`), unknown key, invalid
   length, `dst` too small. Every backend reports the same status for the
   same program.
10. **Canonical encoding**: reserved bytes, unused command slots and unused
    operands must be zero, so a valid program has one byte form.
11. **Reserved ops** (`Read`, `Write`, `Compress`, `Decompress`, `Score`)
    keep their codes, must have zero parameters, and complete with
    `UnsupportedOp` until a contract pull request defines them. `Fft` gets a
    new code in M7.
