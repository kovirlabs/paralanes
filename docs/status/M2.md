## Built

- **`stagelanes-ring`** (`no_std`, `unsafe`):
  - `Ring<T, N>` is a bounded single-producer, single-consumer ring with
    inline power-of-two storage, so it needs no allocator. Each side keeps
    its index on its own 128-byte line. `push_iter` / `pop_with` publish a
    whole batch with one Release store. Each side keeps a cached copy of the
    other side's index.
  - Each side's private position is stored inside the ring. Because of that,
    the ring's `Drop` frees exactly the unread items even after a handle was
    leaked (`mem::forget`) or a callback panicked half-way through a batch.
    Tests cover both cases.
  - Handles come in two forms: borrowed (`split(&mut self)`, for scoped
    threads) or owned (`split_arc`, behind the default `alloc` feature).
  - `RingPair<S, C, N>` pairs a submission ring with a completion ring. It
    caps outstanding requests at `N`, so the completion ring can never be
    full when the server completes a request.
- **`stagelanes-arch`** (`unsafe` only under `platform/`):
  - `Topology::detect` reports:
    - logical CPUs
    - cores
    - sockets
    - NUMA nodes
    - core class (higher = faster)
    - caches and which CPUs share them
    - the maximum frequency the OS reports
  - Per OS:
    - Windows: `GetLogicalProcessorInformationEx`. The buffer is parsed from
      raw bytes at documented offsets, so the parser has no `unsafe`.
    - Linux: sysfs.
    - macOS: `sysctl hw.perflevel*`.
  - The Linux and Windows parsers compile on every OS and are unit-tested
    here against synthetic data: a two-socket, two-node Linux tree;
    Arm-capacity and Intel-hybrid classes; and Windows records spanning two
    processor groups.
  - Also provides `pin_current_thread`, `current_cpu`, `prefetch_read`
    (`prefetcht0` / `prfm`), `ticks` (`rdtsc` / `CNTVCT_EL0`),
    `ticks_per_second` and `measure_core_mhz`.
- **`stagelanes-mem`** (`unsafe` only under `platform/`):
  - `Region` is a committed, pre-touched block of memory. It can use large
    pages, be placed on a NUMA node and be locked in memory. Each region has
    a size cap (default 1 GiB).
    - Windows: `VirtualAllocExNuma`, `MEM_LARGE_PAGES` (needs
      `SeLockMemoryPrivilege`), and `VirtualLock` after growing the working
      set.
    - Linux: `MAP_HUGETLB`, falling back to an `MADV_HUGEPAGE` hint under
      `Prefer`; `mbind` before the pages are touched; `mlock`.
    - macOS: `mlock` only.
  - `BlockPool` splits a region into fixed-size blocks for one owning core.
    `take` and `put` never allocate; a test checks this with a counting
    global allocator.
- **`stagelanes topology [--measure]`** is the CLI.

## Notes and limits

- Each ring's storage sits inside the `Ring` value (a const-generic array).
  Large rings belong in a `Box` or behind `split_arc`. M6 may want a
  heap-backed variant.
- The ring's doctest is `no_run`. Under `--cfg loom`, the ring's atomics only
  work inside a loom model, and the CI loom command also runs doctests. The
  unit tests run the same code.
- On Windows the working-set limit grows with each locked region and does
  not shrink when the region is freed. The limits are soft. This matters
  only for programs that allocate and free many locked regions.
- Every call that grows the working set and locks pages is serialized with a
  start-up-only mutex. The first version raced when tests ran in parallel
  (`ERROR_WORKING_SET_QUOTA`). This is never on a stage core's path.
- `measure_core_mhz` returns `Unsupported` on macOS, because it pins its
  thread first.
