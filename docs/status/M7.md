## Built

### bytelanes: the FFT op (contract change)

- `Op::Fft` (code 10) and `FftParams` (`log2n` from 1 to 16).
  - Input: real `i32` frames.
  - Output: half-spectrum `(i32, i32)` bins, about DFT/N.
  - The algorithm is normative down to every rounding step (see the `Op`
    docs):
    - radix-2 decimation in time
    - Q30 twiddles
    - i64 products rounded with `+2^29 >> 30`
    - each butterfly halved with `>> 1`
    - inputs clamped to ±2^30, so nothing leaves `i32`
- **Why fixed point:** the WGSL spec does not require correctly rounded
  `f32` arithmetic. It allows fused multiply-add, reassociation and flushing
  of subnormals, so a float FFT cannot match the CPU byte for byte (R7).
- **Twiddle table:** `vectors/fft/twiddles.bin` (32,768 pairs) is normative.
  `cpu::fft::twiddles()` rebuilds it from a Taylor series using only `f64`
  add and multiply. CI confirms the rebuilt table equals the committed bytes
  on Linux, Windows and macOS.
- **CPU reference and harness:** `cpu::fft`, `CpuBackend` support,
  `random_case(Op::Fft, seed)`, and 32 new golden vectors (171 in total).
  **The 139 M1 vectors are byte-identical**: the FFT cases use their own
  seed. Cases are only ever added.
- **Merged with M3.** Agent B's wgpu backend (bytelanes#2) merged into
  `main` during this session, so `main` was merged into `m7-fft`. Two small
  changes touch agent B's crate; no shader was edited:
  - `WgpuBackend` now lists its GPU ops in `GPU_OPS` (without `Fft`) for its
    capabilities and its unsupported-op check, so `Fft` completes with
    `UnsupportedOp` until a WGSL FFT exists.
  - Its golden-vector test skips and counts cases whose ops the backend
    does not list, using the new `conformance::Case::runs_on(&Caps)`.

### diagsteno

- **`config`:** the M7 layout; 10 ms ticks; FFT windows of 4096
  accelerometer samples and 1024 strain samples; band edges per kind.
- **`frame`:** the ingest wire format. One frame per channel per tick,
  CRC-32C, per-channel sequence numbers. Acknowledgements are CRC-checked
  too.
- **`synth`:** synthetic data from integer phase accumulators, the Q30 sine
  table and SplitMix64.
  - No floating point, so a seed gives the same bytes everywhere. A test
    pins the output.
  - Signals: accelerometers carry three tones (shaft, gear mesh and bearing
    bands) plus noise. Strain gauges carry tones, an offset and a slow drift.
- **`features`:**
  - Windows are aligned to the absolute sample index, so a replay cuts the
    same windows.
  - Features are mean, RMS, min, max and band energies.
  - The FFT runs through any `bytelanes` `ChannelBackend` as one
    multi-frame program per sensor kind, and each result's CRC is checked.
  - Sums are exact integers, so backend features equal `reference()`
    exactly.
- **`ingest`:** TCP ingest.
  - Each batch is stored durably before it is acknowledged.
  - Missing and duplicate frames are counted from sequence numbers. Each
    channel's position is recovered from the store on restart.
  - Features run on their own thread.
- **`sender`:** real-time paced sending with acknowledgement-delay
  measurement.
- **`diagsteno-store`:** Parquet tables (`samples`, `features`), readable by
  DuckDB, pandas and Polars.
  - Each put goes to a temporary file, is fsynced, renamed into its table,
    and then the directory is fsynced.
  - Open removes leftover temporary files.
  - Each table has its own writer.
- **CLI:** `diagsteno synth | ingest | send | replay | check-store`.

## Measured limits on this machine

From the run file. These are measurements of this guest, not atlas figures.

- **Acknowledgement delay: p50 289 ms, p99 9.2 s, max 9.6 s.** The cause is
  `fsync` latency on this storage stack. A 1 MiB write plus `fsync` takes
  85 ms at p50, and single sample flushes stalled for up to 8.7 s. Storing
  samples kept the disk busy for 45 s of the 60 s run.
- No data was dropped, because the ingest queue holds about 20 s of data.
- The first version had an 8,192-frame queue and fell behind: 1,276 late
  ticks out of 6,000. That run is superseded and was not kept as a run file.
- Headroom is small: about 75% of the time went to storing samples.

## Agent B update (Ryzen, 2026-11-22): the FFT on the GPU

Branches: `bytelanes` `m7-fft-wgsl`, stacked on `m5-atlas`; `paralanes`
`m7-fft-wgsl` (this section, the FFT atlas runs). Evan asked for this after
M5.

Requests 1 to 4 from agent A are done.

1. **Spec review.** The `Op::Fft` spec is implementable exactly in WGSL; no
   contract change is needed.
   - The only care point is the halving. `(u + t) >> 1` can exceed `i32`
     before the shift. WGSL uses `(u>>1) + (t>>1) + (u & t & 1)`, and the
     matching difference form; both equal the specified floor.
   - The 64-bit products are pairs of `u32`, with a sign correction.
2. **The WGSL FFT is built.**
   - `GPU_OPS` now includes `Fft`, so no golden case is skipped any more.
   - The twiddle table is uploaded once from `twiddle_bytes()`.
   - The first 10 stages are fused in workgroup memory.
3. **Replayed.**
   - All 171 golden vectors (log2n 1 to 16, and
     `program/decrypt-fft-checksum`) pass on Vulkan and DX12.
   - `random_case(Op::Fft, seed)` for seeds 0..10000: 0 failed on each API.
   - New large inputs: 4,096-point FFTs over 64 MiB (a 2D grid), and
     65,536-point FFTs over 32 MiB at an unaligned offset.
   - Mutation checks: dropping the halving's floor correction fails 16
     golden vectors; dropping the multiply's sign correction fails 17.
4. **diagsteno's GPU half of "features equal the CPU reference": pass.**
   - Method: a temporary worktree of `m7-ingest-features`, with a
     temporary test and a dev-dependency on `bytelanes-wgpu` (nothing
     committed to diagsteno).
   - `Engine::new(WgpuBackend)` over 10 s of synthetic data
     (`Synth::new(default_layout(), 2026, …)`) gave **2,272 of 2,272
     windows equal to `features::reference`, on Vulkan and on DX12.**
   - Suggestion for agent A: keep a version of this test in diagsteno
     behind a `gpu` feature, so the self-hosted GPU runner can run it.
5. **Agent A's two edits to `bytelanes-wgpu`:** reviewed and kept. The
   `GPU_OPS` list now names `Fft`. The skip in `tests/conformance.rs` stays
   useful for backends that lack an op, such as agent C's Metal backend
